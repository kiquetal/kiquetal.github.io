MAP vs FLATMAP

Two-Track Railway Behavior in Functional Error Handling (ROP)
Bilingual Guide: EN (English) / ES (Español)

.map(T → U)

Transforming Value: Applies a one-track function to the Success side. Always remains on the Success track!
Transformación: Aplica una función de una vía al éxito. ¡Siempre se mantiene en la vía de éxito!

Ok → Err →
Mapper Function Function<T, U>
Ok(U)
Err(E)
✦ Passes through function!
¡Pasa por la función!
✦ Bypasses function completely on Err!
¡Se desvía y omite la función por completo!
Note: If Result is Err, map() does NOT call the function. It instantly bypasses to keep the error unchanged.

.flatMap(T → Result<U, E>)

Chaining Operations: Applies a function that returns a new Result. This allows switching (derailing) to the Error track!
Encadenamiento: Aplica una función que devuelve un Result. ¡Permite cambiar a la vía de error!

Ok → Err →
Track-Switching Fn Function<T, Result<U,E>>
Ok(U)
Err(E)

to Error track here!
¡Puede desviarse aquí si falla!
✦ Bypasses function completely on Err!
¡Se desvía y omite la función por completo!
Note: If any step fails, flatMap() bypasses all subsequent mapper functions, allowing the error to slide straight to the end.
ROP Principles:
• Success values flow on the Green track, entering boxes.
• Error values flow on the Red track, bypassing all boxes. Principios ROP:
• El éxito fluye por la vía verde, entrando en las cajas.
• El error fluye por la vía roja, omitiendo todas las cajas.
