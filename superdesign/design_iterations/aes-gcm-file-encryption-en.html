Client-Side File Encryption

AES-GCM-256 with Passphrase-Based Key Derivation

✦ ❦ ✦
1

Generate Random Salt

Create a cryptographically secure random salt for PBKDF2.

Salt Size: 16 bytes (128 bits)
⚠ Salt must be unique for each encryption. Store it with the encrypted file.
↓
2

Derive Encryption Key with PBKDF2

Convert user passphrase into a strong encryption key using PBKDF2-HMAC-SHA256.

Input: User Passphrase (string)
Salt: 16 bytes (from Step 1)
Iterations: 100,000+ (recommended: 600,000)
Hash Function: HMAC-SHA256
Output Key: 32 bytes (256 bits)
Higher iterations = stronger protection against brute-force attacks
↓
3

Generate Initialization Vector (IV)

Create a random IV for AES-GCM encryption.

IV Size: 12 bytes (96 bits)
⚠ IV must be unique for each encryption with the same key. Never reuse!
↓
4

Encrypt File with AES-GCM-256

Encrypt the file content using AES in Galois/Counter Mode.

Algorithm: AES-GCM
Key: 32 bytes (from Step 2)
IV: 12 bytes (from Step 3)
Input: File content (plaintext)
Output: Encrypted content (ciphertext)
↓
5

Generate Authentication Tag

AES-GCM automatically produces an authentication tag during encryption.

Tag Size: 16 bytes (128 bits)
The tag ensures data integrity and authenticity. Decryption will fail if data is tampered with.
↓
6

Construct Final Encrypted File

Combine all components into a single encrypted file.

File Structure:
[Salt: 16 bytes] + [IV: 12 bytes] + [Ciphertext: variable] + [Tag: 16 bytes]
  • Salt and IV are stored in plaintext (not secret)
  • Total overhead: 44 bytes (16 + 12 + 16)
  • File can be decrypted with the correct passphrase
✦
